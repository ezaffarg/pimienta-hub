# Fase 2.20X-F — Scheduler + event operations observability

Fecha: 2026-08-28. Estado: **LOCAL IMPLEMENTATION + VALIDATION PASS**.

## Objetivo y alcance

Agregar una invocación server-only acotada que coordine eventos `received`,
retries due y recuperación `missed_feeds`, reutilizando intake X-B, claim/lease
X-D y retry policy X-E. El mismo bloque agrega observabilidad persistente y una
lectura administrativa mínima para Owner/Manager.

## Decisión de orchestration

Cada Connection Mercado Libre activa obtiene un maintenance run tenant-bound.
El run funciona como lock compatible por Connection, conserva la continuación
de `missed_feeds` y registra estado, timestamps, counters y errores seguros. No
se agrega lock global: los leases/CAS de eventos siguen siendo la autoridad que
impide doble procesamiento.

El ciclo tiene presupuestos explícitos y no contiene daemon, `while(true)` ni
`setInterval`. Una falla queda aislada al evento o Connection afectada.

## Scheduler trigger

El repositorio documenta Vercel y Docker self-hosted, pero no selecciona un
deployment productivo ni contiene cron/configuración de scheduler. Por lo
tanto, X-F implementa el servicio invocable y deja el trigger en
`ORCHESTRATION_READY_SCHEDULER_TRIGGER_BLOCKED`; no inventa plataforma,
credenciales ni endpoint público. El manual trigger también queda diferido.

## Observabilidad y seguridad

La lectura administrativa expone backlog y counters agregados sin payloads,
tokens ni errores raw. Exige sesión, Organization y membership persistente
Owner/Manager. Employee y Client quedan denegados. Tabla y RPCs permanecen
exclusivamente bajo `service_role`.

## Exclusiones

No provider real, scheduler real, remote apply, webhook real, OAuth, refresh,
listing sync real, daemon, rediseño del dashboard ni cierre Git.
