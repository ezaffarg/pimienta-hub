# Fase 2 — 2.20F: Safe Mercado Libre token refresh rotation

## Mandato operativo

Implementar localmente y antes de cualquier refresh real una primitive server-only `getValidAccessToken(connection)` para Mercado Libre. El access token de E.A.ZOCOOL está vencido y el refresh token existe sólo cifrado. No se ejecutará refresh real, llamada adicional a Mercado Libre, sync real, escritura remota, `git add`, commit ni push.

La primitive debe reutilizar un token vigente, coordinar requests concurrentes por Connection, evitar refresh duplicado, soportar la rotación de refresh token, cifrar y persistir las credenciales juntas de forma atómica, y devolver el token únicamente en memoria server-side.

Se auditarán únicamente `integration_secrets`, repositories/primitives de Connection, cifrado, OAuth client Mercado Libre, las evidencias 2.20A/2.20E, migrations, convenciones transaccionales y tests OAuth.

### Diseño obligatorio

- Dos requests que observan el refresh token N no pueden refrescarlo simultáneamente ni permitir que un writer stale sobrescriba N+1.
- Preferir coordinación PostgreSQL por Connection, pero no mantener una transacción o lock de DB durante `POST /oauth/token`.
- Introducir sólo metadata mínima: versión monotónica de credencial, claim/lease identificable y expiración recuperable sin cron.
- Después de obtener un claim, releer las credenciales. Si un peer ya dejó un token vigente, no llamar al proveedor.
- La persistencia debe ser compare-and-swap: sólo actualiza si coinciden `credential_version` y lease owner. Si falla, relee; jamás sobrescribe.
- El lease debe ser corto y recuperable. El refresh HTTP no tiene retry ciego.
- Aplicar una ventana de seguridad antes de expiry, sin refrescar demasiado pronto.

### Refresh Mercado Libre

Usar `POST /oauth/token` con `grant_type=refresh_token` exclusivamente server-side. Validar con Zod access token, `expires_in`, token type, scope opcional y refresh token rotado. La ausencia de `refresh_token` en un refresh se considera respuesta inválida: no se persiste un valor vacío ni se destruyen las credenciales anteriores. Si el refresh falla, se libera el claim y se comunica necesidad de reconexión mediante un error normalizado, sin desactivar automáticamente la Connection.

Nunca loggear, devolver, poner en Sentry/audit metadata o persistir plaintext de access token, refresh token, client secret, authorization code, state o master key.

### Matriz obligatoria

1. token vigente: no refresh;
2. token vencido: una rotación N a N+1;
3. refresh token rotado cifrado antes de persistir;
4. fallo HTTP: credenciales previas preservadas;
5. writer stale/CAS rechazado: sin overwrite;
6. concurrencia simulada: un ganador y el otro relee;
7. lease vencido: recuperable;
8. respuesta malformada: sin persistencia parcial;
9. RLS/grants server-only;
10. ausencia de browser/token leakage.

Si se requiere migration, debe ser forward-only, mantener RLS enabled, cero policies browser-facing, `PUBLIC`/`anon`/`authenticated` denegados y `service_role` server-only. Ejecutar pruebas relevantes, typecheck, lint, `supabase db reset` si existe migration y `git diff --check`; no build salvo cambio de ruta/UI.

## Resultado local

La migración forward-only `20260825100000_safe_integration_secret_refresh_rotation.sql` agrega `credential_version`, `refresh_lease_id` y `refresh_lease_expires_at` a `integration_secrets`, y tres RPCs `SECURITY DEFINER` con `search_path=pg_catalog`: claim, complete CAS y release. Un trigger incrementa la versión y borra el lease cuando un flujo autorizado diferente actualiza credential material, de modo que reconnect tampoco puede ser sobrescrito por un refresh stale. El claim usa una transacción corta y lease de 60 segundos; la llamada HTTP tiene timeout de 15 segundos y sucede fuera de DB. La ventana de expiración es 120 segundos.

`MercadoLibreCredentialService.getValidAccessToken()` es server-only. Mercado Libre refresca con `grant_type=refresh_token`; exige el refresh token rotado y persiste ambos envelopes cifrados junto con expiry, metadata allowlisted y versión. La integración de listings ahora consume esa primitive y no descifra tokens directamente.
