# Fase 2.20W-B — Safe run-aware listing reconciliation

## Objetivo y contratos

Implementar reconciliación interna, reversible y run-aware para Listings. El
diseño parte del [audit W-A](./2.20w-a-listing-reconciliation-design-schema-audit.md)
y de la [resolución provider-specific W-A2](./2.20w-a2-provider-reconciliation-semantics.md):
ausencia no significa `closed`, `deleted` ni `removed`.

## Scope y exclusiones

Incluye migration local, persistencia positiva ligada al run, transición
`seen ↔ missing_candidate`, counters agregados, finalize atómico, tests y
documentación focalizada. Excluye `confirmed_missing`, deletes, inferencia de
status, provider calls, writes remotos, scheduler y cierre Git.

## Schema, implementación y validación

La migration `20260827150000_safe_listing_reconciliation.sql` agrega los campos
de evidence/counters, la FK compuesta scoped, un índice usado por el candidate
set y dos RPC server-only. La persistencia positiva es run-aware; el adapter
valida final de paginación, modo, total, cursores, fallos y counters; el finalize
aplica missing transitions y estado terminal atómicamente.

La matriz SQL local cubre schema, backfill, constraints, grants, positive seen,
missing repetido, reappearance, idempotencia, recovery y old-run protection.
Los tests TypeScript cubren mapping, caller, completitud fail-closed y read model.
Las regresiones T/U/V permanecen incluidas en el gate local.

Resultado local: matriz W-B 14/14, focalizados 101/101, regresiones SQL T/U
34/34, suite completa 236/236, typecheck y lint PASS.

## Validación remota autorizada — W-C

W-C autoriza aplicar una única vez la migration W-B y validarla sólo con
fixtures sintéticos aislados. Los recursos reales deben permanecer intactos;
provider calls, OAuth, reconnect, refresh y listing sync real permanecen en 0.

## Resultado remoto W-C

La migration W-B quedó aplicada una sola vez. La validación remota con 24 filas
base sintéticas y 7 audits agregados confirmó schema, defaults, grants,
aislamiento compuesto, positive seen, missing inicial y repetido, reappearance,
non-eligible runs, recovery administrativa, idempotencia y old-run protection.
El cleanup dejó 0 fixtures; conteos y huellas de los recursos reales coinciden
con el baseline. Provider calls y operaciones OAuth/sync: 0. W-C pasa, pero
su cierre formal requería un mandato separado.
