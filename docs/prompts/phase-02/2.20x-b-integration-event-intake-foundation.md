# Fase 2.20X-B — Integration event intake foundation

Fecha: 2026-08-28. Estado: **LOCAL IMPLEMENTATION + VALIDATION PASS**.

## Contrato y scope

X-B implementa la foundation local server-only aprobada en
[2.20X-A](./2.20x-a-incremental-sync-notifications-design-audit.md): envelope
canónico, parser Mercado Libre `items`, resolución de Connection por identidad
provider, deduplicación durable y atomic intake.

Quedan excluidos el callback público, firma/HMAC, ACK HTTP, worker, provider
fetch, actualización de Listings, retries, `missed_feeds`, scheduler, UI,
operaciones remotas y cierre Git. No se persisten payloads raw, headers ni
secretos.

## Implementación local

- una migration forward-only para `integration_events` y su RPC de intake;
- repository/modelo canónico en infraestructura;
- parser `items` y servicio de resolución/intake en la integración Mercado
  Libre;
- matriz SQL y tests TypeScript de parser, resolver, dedupe, scope y seguridad.

## Validación y checkpoint

- reset local desde cero: PASS;
- matriz SQL X-B: 9/9 PASS;
- tests focalizados de parser/intake/repository: 24/24 PASS;
- regresión focalizada de Connection, OAuth, listings y recovery: 133/133 PASS;
- suite completa: 260/260 PASS;
- typecheck: PASS;
- lint: PASS, 0 warnings y 0 errors.

La deduplicación usa `(provider, application_id, dedupe_key)`. Mercado Libre
`items` deriva una key estable desde el identificador externo cuando existe y,
en su ausencia, desde los campos canónicos del evento; `attempts` y `received`
no cambian la identidad lógica. El intake resuelve la Connection activa por la
identidad provider y deriva desde base Organization, Store y Connection.

No se ejecutaron operaciones remotas, callbacks públicos, provider calls,
OAuth, refresh, worker, procesamiento de eventos, actualización de Listings ni
cierre Git. El backlog/lease del futuro worker continúa diferido hasta definir
su semántica operativa.
