# 2.20X-F3-C1 — Remote Production Readiness Audit

## Objetivo

Descubrir de forma read-only el estado real de la infraestructura productiva
antes del primer deployment de Pimienta Hub.

## Baseline

- Repositorio: `ezaffarg/pimienta-hub`.
- Rama: `develop`.
- Base esperada: `c6dc39a45bf98a0641809d3cdca2b500cfe6c11a`.
- R1, R2 y el cierre acumulado X/F3-B están completos.
- Target canónico: Hostinger VPS → Ubuntu LTS → Docker → Coolify.

## Alcance

- Verificar acceso SSH, sistema operativo, arquitectura y recursos del VPS.
- Detectar Docker, Coolify, Applications existentes y conexión al repositorio.
- Identificar el estado de dominio, DNS y TLS.
- Inventariar variables productivas sin mostrar valores.
- Consultar read-only el estado remoto de las cinco migrations X.
- Definir el mecanismo recomendado del scheduler y el plan ordenado F3-C2.

## Exclusiones

No desplegar, crear o editar recursos de Coolify, ejecutar migrations o SQL,
modificar DNS/TLS/firewall, configurar providers, crear el scheduler ni hacer
writes contra Supabase, Clerk, Mercado Libre, Sentry o Hostinger.

## Validación local

No se repiten tests, typecheck, lint ni build. Como este bloque sólo modifica
documentación, la única validación local requerida es `git diff --check`.

## Estado

F3-C1 es una auditoría remota read-only. F3-C2 no comienza hasta entregar su
checkpoint y resolver cualquier acción requerida al usuario.
