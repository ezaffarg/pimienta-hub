# 2.20X-F3-C-LOCAL-2D — Mercado Libre public HTTPS + provider test

## Objetivo

Validar el tramo Mercado Libre pendiente desde el deployment Coolify local,
expuesto temporalmente mediante HTTPS público, sin convertir el laboratorio en
infraestructura productiva.

## Alcance autorizado

- Iniciar exactamente un Cloudflare Quick Tunnel hacia la aplicación local.
- Validar health, root y callback público con payload sintético seguro.
- Determinar las URLs temporales exactas de OAuth y notifications.
- Actualizar únicamente las URLs necesarias en Mercado Libre Developers cuando
  exista control seguro; de lo contrario, detenerse para acción manual.
- Preferir la Connection existente y realizar como máximo una comprobación
  server-side de identidad, con refresh sólo si surge naturalmente.
- Ejecutar exactamente una invocación válida del mantenimiento incremental.
  Esta ejecución puede realizar las llamadas Mercado Libre derivadas de
  `missed_feed_due=true`.
- Inspeccionar metadata segura, counters, logs y readiness del scheduler.

## Límites

- No realizar listing sync amplio, polling repetido ni escrituras al provider.
- No crear scheduler recurrente, infraestructura Hostinger/VPS, DNS o TLS
  permanente.
- No imprimir secretos, tokens, headers sensibles ni payloads de cliente.
- No hacer escrituras manuales en Supabase ni cambios Clerk.
- Preferir cero cambios productivos; un defecto real se reporta sin parchearlo.
- La URL `trycloudflare.com` es temporal y no entra en configuración canónica.
- No hacer commit ni push en este bloque.

## Baseline

- Base Git: `6f6a400d0983c30f764db049c41abeb3bd82799e`.
- Coolify local, health, Supabase remoto y cinco migrations X: PASS.
- Credenciales rotadas y server-only; legacy Supabase deshabilitadas.
- Intake, idempotencia, CAS, retry y stale reclaim: PASS.
- La Connection real tiene `missed_feed_due=true`; las provider calls previas de
  F3-C fueron cero.

## Gate de salida

El checkpoint debe separar alcance público, estado de URLs, identidad,
maintenance, efectos DB, provider-call budget, cleanup y readiness del
scheduler. El tunnel puede detenerse al finalizar y no debe convertirse en
configuración permanente.
