# 2.20X-F3-C-LOCAL-2D3 — Mercado Libre real provider test

## Objetivo

Validar el boundary real de Mercado Libre usando la Connection existente, el
tunnel HTTPS temporal ya activo y una única ejecución controlada de
mantenimiento.

## Alcance autorizado

- Reutilizar exclusivamente el hostname temporal declarado; no reiniciar ni
  reemplazar el tunnel.
- Verificar alineación exacta entre redirect de Mercado Libre Developers y el
  runtime Coolify.
- Inspeccionar metadata segura de Connection y credenciales cifradas.
- Realizar como máximo una verificación canónica de identidad, con refresh sólo
  si surge naturalmente.
- Ejecutar exactamente una llamada válida al endpoint interno de maintenance;
  las lecturas Mercado Libre producidas por esa ejecución quedan autorizadas.
- Auditar counters, cursor, retries, persistencia y readiness del scheduler sin
  ejecutar una segunda maintenance.

## Límites

- Sin scheduler recurrente, Hostinger/VPS, DNS productivo ni infraestructura
  permanente.
- Sin escrituras manuales en DB, cambios Clerk o mutaciones de negocio en
  Mercado Libre.
- No modificar `next.config.ts`, producto, migrations, Dockerfile o env example.
- No imprimir secretos, tokens, headers sensibles ni payloads de cliente.
- Un mismatch de URL, cambio de tunnel o defecto runtime detiene provider work
  hasta resolver el gate correspondiente.
- No hacer commit ni push.

## Gate de salida

El checkpoint debe separar estabilidad del tunnel, redirect, Connection,
identidad, provider-call budget, maintenance persistida, missed feeds,
observabilidad y readiness del scheduler.
