# Fase 2.20X-E — Retries + missed_feeds recovery

Fecha: 2026-08-28. Estado: **LOCAL IMPLEMENTATION + VALIDATION PASS**.

## Objetivo y contratos heredados

Agregar capacidad server-only controlada para programar y despachar retries de
eventos X-D, y recuperar notificaciones Mercado Libre `items` desde
`GET /missed_feeds` sin convertir ese feed en source of truth.

Se preservan X-B intake/dedupe, X-C callback+ACK y X-D claim/lease, fetch
canónico, freshness CAS y lifecycle. Todo feed recuperado debe volver a pasar
por el intake X-B antes de cualquier procesamiento.

## Retry policy

El modelo debe conservar `failed + retryable`, agregar evidencia durable de
`next_retry_at`, respetar Retry-After válido y limitar attempts. La selección
due no reclama ni incrementa attempts; el processor X-D mantiene la única
primitive de claim y el único flujo de actualización de Listings.

## Semántica missed_feeds

La documentación oficial vigente exige Bearer token, `app_id`, `topic=items` y
`site_id`; ofrece paginación por `limit/offset` y una retención de hasta dos
días. El site se resolverá mediante identidad oficial `/users/me` y se
cotejará con la Connection persistida antes del feed.

## Exclusiones

No scheduler, cron, daemon, loop automático, UI, route pública de proceso,
provider calls reales, webhook real, sync real, remote apply/writes ni cierre
Git. Provider e identidad se validan sólo con mocks/fixtures.

## Tests y checkpoint

La migration X-E mantiene `failed + retryable`, agrega `next_retry_at`, limita
los claims a cinco attempts y calcula backoff exponencial determinista con base
30 segundos, máximo local de una hora y jitter hash de 0–25 %. Un Retry-After
válido actúa como piso temporal.

El dispatcher acotado lista eventos due y reutiliza `MercadoLibreEventProcessor`.
El recovery de missed feeds resuelve Connection y credencial, consulta
`/users/me` para verificar identidad y `site_id`, pagina con `limit=10` y
`offset`, y entrega cada mensaje canónico al intake X-B.
Cada invocación consume como máximo diez páginas y devuelve un `nextOffset`
explícito cuando aún no alcanzó el final.
