# 2.20X-F3-C-LOCAL-2D3C12 — Credential resolution runtime gap

## Objetivo

Diagnosticar sin nuevas ejecuciones reales por qué el maintenance X-F falló en
`credential_resolution` antes de alcanzar Mercado Libre, verificar el secreto
persistido mediante el path canónico y aplicar sólo el fix local mínimo si la
causa quedaba probada.

## Límites

- Cero provider calls, maintenance retries, OAuth, reconnect, refresh o
  scheduler.
- Base remota y runtime inspeccionados únicamente mediante lecturas seguras.
- Sin exposición de tokens, ciphertexts, claves ni payloads del provider.
- Sin mutación manual de Connection, Store o credenciales.

## Root cause confirmado

`MercadoLibreMissedFeedRecoveryService.recoverItems()` entregaba a
`MercadoLibreCredentialService.getValidAccessToken()` el scope completo de
recovery, incluyendo `offset` y `maxPages`. El servicio de credenciales valida
un input estricto que admite sólo `organizationId` y `connectionId`; por eso el
runtime fallaba antes de leer o descifrar el secreto y registraba correctamente
cero provider calls.

El secreto real existe, está vigente, usa key version 1 y ambas credenciales se
descifraron correctamente con el repository canónico y la configuración del
container desplegado. El fix proyecta explícitamente el scope canónico antes de
invocar el servicio de credenciales y agrega regresión focalizada.
