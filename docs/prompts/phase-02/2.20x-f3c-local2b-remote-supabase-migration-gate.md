# 2.20X-F3-C-LOCAL-2B — Remote Supabase Migration Gate

## Objetivo

Aplicar exclusivamente las cinco migrations 2.20X aprobadas al proyecto
Supabase remoto linked y validar historial, objetos, seguridad, aislamiento y
salud de la aplicación local desplegada.

## Write gate autorizado

La autorización remota se limita a:

1. `20260828120000_integration_event_intake_foundation.sql`
2. `20260828150000_incremental_event_processing_freshness_cas.sql`
3. `20260828180000_event_retries_missed_feeds_foundation.sql`
4. `20260828210000_event_maintenance_observability.sql`
5. `20260828223000_maintenance_run_stale_reclaim.sql`

Antes del write deben pasar identidad remota inequívoca, backup/recovery,
auditoría completa de SQL, orden y consistencia del historial. No se autoriza
`migration repair`, reset, seeds, schema overwrite ni migrations futuras.

## Validación

Después del apply se debe releer el historial, inspeccionar objetos y grants,
verificar RLS/tenant isolation y descartar pérdida de datos. Las matrices SQL
sólo pueden ejecutarse si sus transacciones, fixtures y rollback son seguros
para el remoto compartido.

## Exclusiones

No modificar Coolify salvo necesidad documentada, no tocar Supabase local,
Clerk, Mercado Libre, Sentry, scheduler, tunnel, DNS o VPS. No cambiar código
productivo ni ejecutar suites generales sin una incompatibilidad real.

## Estado

LOCAL-2B es el gate remoto separado entre el deployment local saludable y la
validación runtime LOCAL-2C.
