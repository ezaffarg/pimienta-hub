## Resultado

La definición remota efectiva de `claim_integration_secret_refresh`,
`complete_integration_secret_refresh`, el trigger de versionado y sus grants
coincide con la migration canónica. Claim conserva la versión; complete exige
Organization, Connection, versión, lease owner y lease vigente, retorna un
booleano e incrementa exactamente una vez.

Dos reproducciones sintéticas remotas pasaron con cleanup total: una invocó
claim/complete mediante Supabase RPC y otra recorrió el servicio, repository,
cifrado y provider mock canónicos. Ambas produjeron `3 → 4`, reemplazo atómico
y lease limpio. Un lease real no se reutilizó y no hubo llamadas a Mercado
Libre, maintenance ni scheduler.

El incidente real fue `REFRESH_COMPLETE_RPC_FAILED`, no el `false` que activa
el diagnóstico de predicados CAS. El subtipo seguro (`CAS_RPC_THROW`,
`CAS_RPC_ERROR`, `CAS_RESPONSE_INVALID` o error previo no clasificado) no quedó
preservado por el harness operativo original. Tras el release tampoco existe
evidencia durable del lease histórico. Por eso no puede atribuirse honestamente
a versión, owner, expiración o retorno, y no se autoriza un parche especulativo
ni una migration. Estado: `REFRESH_CAS_GAP_REMAINS`.
