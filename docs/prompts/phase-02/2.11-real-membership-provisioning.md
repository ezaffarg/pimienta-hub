## Mandato archivado

Este documento archiva el mandato completo recibido para la Subfase 2.11. Su alcance autoriza únicamente la preparación e implementación de primitivas server-only para provisioning de memberships persistentes y asignaciones de Store, con validación tenant-scoped, tests deterministas y actualización documental. No autoriza datos reales, migraciones, cambios de schema remoto, OAuth, Fase 3 ni operaciones Git.

### Alcance operativo

- Provisionar memberships mediante una primitiva equivalente a `provisionMembership({ targetClerkUserId, role })`.
- Derivar siempre la Organization y el actor desde el contexto server-side; nunca aceptar `organizationId` ni actor/rol del navegador.
- Autorizar inicialmente únicamente a Owner; Manager, Employee y Client deben denegarse.
- Verificar que el target sea miembro Clerk de la Organization activa; no crear cuentas Clerk.
- Devolver resultados controlados para duplicados (`already_exists`) sin sobrescribir roles silenciosamente.
- Mantener la seguridad del último Owner como invariante de servicio; no realizar migraciones automáticas.
- Preparar `assignStoreToMembership` y `revokeStoreFromMembership`, permitiendo Employee/Client, denegando Owner/Manager, y validando pertenencia a la Organization activa.
- Resolver membership y Store por identificadores no confiables bajo el tenant activo; no realizar deletes globales.
- Usar fixtures deterministas ficticios; no crear usuarios, Stores, memberships o nombres reales.
- Cubrir tests de autorización, pertenencia Clerk, duplicados, cross-tenant, asignación/revocación y flujo completo de scope.
- No implementar auditoría, OAuth, Mercado Libre, UI, Fase 3, nuevas migraciones ni cambios remotos.
