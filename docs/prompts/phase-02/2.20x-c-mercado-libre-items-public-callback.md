# Fase 2.20X-C — Mercado Libre public items callback

Fecha: 2026-08-28. Estado: **LOCAL IMPLEMENTATION + VALIDATION PASS**.

## Objetivo y boundary

Agregar un único `POST /api/integrations/mercado-libre/notifications/items`
público server-to-server que limite su trabajo a request, validación, resolución
de Connection, intake durable X-B y ACK inmediato. Reutiliza el parser, service,
repository y dedupe de X-B; el request nunca elige Organization, Store o
Connection.

## Seguridad y ACK

El body queda limitado, se valida de forma estricta y no se registra ni se
persiste raw. La identidad se apoya en la application server-side, el topic y
resource allowlisted, la Connection activa y la deduplicación durable. La
documentación oficial recomienda HMAC-SHA256, pero no publica un contrato
implementable de header/canonicalización/secreto; X-C no inventa una firma.

| Condición | HTTP | Retry esperado | Persistido |
| --- | ---: | --- | --- |
| `ACCEPTED` | 200 | no | sí |
| `DUPLICATE` | 200 | no | sí, fila previa |
| JSON/body/envelope inválido | 200 | no | no |
| application incorrecta | 200 | no | no |
| Connection inexistente o binding inválido | 200 | no | no |
| resolución ambigua/transitoria | 503 | sí | no |
| configuración server-side inválida | 503 | sí | no |
| fallo transitorio de intake | 503 | sí | no confirmado |

Las respuestas no incluyen IDs internos, datos DB, secretos ni trazas.

## Exclusiones

No se implementan provider fetch, procesamiento, Listing writes, worker,
retries internos, `missed_feeds`, scheduler, rate limiter distribuido, OAuth,
refresh, reconnect, operaciones remotas, exposición pública real ni cierre Git.
